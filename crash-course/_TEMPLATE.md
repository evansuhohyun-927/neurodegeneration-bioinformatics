# Crash Course 가이드 작성 규칙

**독자:** 생물학/의학 배경이 있고, 당장 며칠 안에 해당 분야 데이터를 분석하거나 논문을 읽어야 하는 사람. 코딩은 초급.
**목적:** 한 파일을 30–45분 읽으면 "이 분야 분석이 무엇을 재고, 어떤 순서로 처리하고, 어디서 틀리기 쉬운지"를 알고 바로 시작할 수 있게 한다. 본 과정 레슨(하루 75–90분, 자세한 설명)과 달리 **압축된 참조 문서**다.
**톤:** 한국어, 짧은 문단과 표 위주. 용어는 처음 나올 때 영어 원어 병기. 원리 설명은 직관 수준으로 짧게, "언제 무엇을 쓰는가"와 "하지 말아야 할 것"에 분량을 쓴다.

## 파일 구조 (이 순서, 이 제목 그대로)

```markdown
# Crash Course — <분야>

> **읽는 시간:** 30–45분 · **이 가이드로 할 수 있는 것:** 한 문장

## 한눈에 보기
무엇을 측정하는가 / 어떤 질문에 답하는가 / 답하지 못하는 것 — 표 하나.

## 🎬 급할 때 볼 영상
2–3개. 제목 — 채널 (길이) + 한 줄 "왜 이 영상인가".

## 핵심 개념 10개
용어 | 한 줄 정의 | 왜 중요한가 — 표.

## 측정 기술 고르기
기술별 표: 무엇을 얻나 / 장점 / 한계 / 이런 질문에 쓴다.

## 표준 분석 흐름
원자료 → 결과까지 단계 번호 목록. 각 단계: 하는 일, 대표 도구(무료·공개 도구 우선), 입력→출력 파일 형식, 이 단계의 QC 기준.

## 최소 실행 예시
작은 가상 데이터로 흐름의 핵심 한 단계를 보여 주는 Python 코드 1–2개 + 실제 출력. numpy/pandas/scipy/scikit-learn/statsmodels/matplotlib만 사용.

## 흔한 함정
6–8개. "이렇게 하면 → 이런 문제 → 대신 이렇게".

## 연구 설계 체크리스트
분석 시작 전에 확인할 것 체크박스 8–10개 (표본 수, 반복, 배치, 대조군, 메타데이터, 다중검정 등).

## 공개 데이터와 더 볼 곳
공개 저장소(이름 + 공식 URL + 무엇이 있나), 공식 문서·튜토리얼, 핵심 리뷰 논문(실재 확인된 것만, DOI 또는 PMID).

## 본 과정과의 연결
이 저장소의 어느 레슨이 어느 부분을 자세히 다루는지 상대 링크로.

---
[Crash Course 목록](README.md) · [코스 지도](../README.md)
```

## 반드시 지킬 것

1. **영상 링크는 실재해야 한다.** 모든 YouTube 링크를 `curl -s "https://www.youtube.com/oembed?url=https://www.youtube.com/watch?v=<ID>&format=json"`로 확인하고 확인된 제목을 쓴다. 안 되면 YouTube 검색 링크로 대체하고 "(검색 링크)"라고 표시한다.
2. **도구·데이터베이스·논문을 지어내지 않는다.** URL은 실제로 열리는지 확인한다(봇 차단으로 403이면 그렇게 보고). 논문은 PubMed/Crossref로 서지를 확인한 것만 쓴다. 기준값(예: QC 문턱)은 "흔히 쓰는 출발점"임을 밝히고 근거가 되는 공식 문서를 건다.
3. **코드는 실제 실행해 출력을 붙인다.** 아무것도 설치하지 않는다. 실제 데이터 파일이 필요한 단계는 코드 없이 도구 이름과 명령의 형태만 적는다.
4. **공개 저장소용 저작권 규칙:** 영상·웹페이지·논문·교재의 문장을 옮겨 적지 않는다(자기 말로). 외부 이미지 삽입 금지. 개인 절대 경로, 특정 학교·강의·교수 언급 금지.
5. **과장 금지:** 진단·치료 주장을 하지 않고, 탐색적 분석과 확증적 분석을 구분한다.
6. 자기에게 배정된 파일만 만든다. 다른 파일은 수정하지 않는다.
