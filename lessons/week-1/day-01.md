# Day 1 — 과정의 범위와 한계, 그리고 프로젝트의 첫 commit

> **주차:** 1주차 · **예상 시간:** 75–90분 · **산출물:** `README.md`, 첫 commit

## 오늘의 목표
- 이 과정이 답하려는 질문과, 답하지 **않는** 질문을 구분해서 말할 수 있다.
- 6주 동안 쓸 프로젝트 폴더 구조를 만들고 `README.md`에 범위와 한계를 적을 수 있다.
- 지금 상태를 Git commit으로 남길 수 있다.

## 개념 설명

### 이 과정이 답하는 질문, 답하지 않는 질문

6주 동안 우리가 붙들고 갈 질문은 하나입니다. "우주비행 관련 마우스 뇌의 신경염증·산화스트레스 분자 변화와, 파킨슨병 환자의 운동 표현형은 퇴행성 신경질환 연구에서 어떤 기전적 가설을 **제안**할 수 있는가?" 여기서 가장 중요한 단어는 '제안'입니다. 이 과정은 가설을 **만드는** 연습이지, 가설을 **입증하는** 연구가 아닙니다.

임상에 비유하면 이렇습니다. 외래에서 환자 한 명을 보고 "이런 기전이 아닐까?" 하고 감별진단 목록을 적는 것과, 무작위 대조 임상시험으로 치료 효과를 입증하는 것은 전혀 다른 수준의 일이지요. 우리는 앞쪽을 합니다. 그래서 이 과정에서는 다음 세 가지를 **말하지 않습니다.**

1. "우주비행이 파킨슨병을 일으킨다" (인과 주장)
2. "이 사람은 파킨슨병이다 / 아니다" (개인 진단)
3. "이 유전자를 조절하면 치료된다" (치료 권고)

이 세 문장은 6주 내내 금지어라고 생각하세요. 분석을 잘하는 것만큼, 결과를 과장하지 않는 것이 이 과정의 평가 기준입니다.

### 두 데이터는 왜 합치지 않는가

우리가 쓸 데이터는 두 가지입니다. NASA OSDR의 OSD-536은 **마우스 뇌 조직**의 유전자 발현(분자) 데이터이고, PhysioNet의 PADS는 **사람**이 스마트워치를 차고 수행한 운동 평가 데이터입니다. 종이 다르고, 측정한 대상(조직 대 손목 움직임)이 다르고, 같은 개체도 아닙니다.

두 데이터를 한 표에 합쳐 통계를 돌리는 것은, A 병원 환자의 혈액검사 결과와 B 병원 다른 환자의 MRI를 한 사람의 차트에 붙여 넣는 것과 같습니다. 숫자는 계산되지만 의미가 없습니다. 그래서 이 과정에서는 프로젝트를 **두 개로 따로** 진행하고, 마지막 주에 "두 결과가 공통으로 가리키는 기전(염증, 산화스트레스 등)이 문헌상 있는가?"를 **글로만** 연결합니다. 숫자로는 연결하지 않습니다.

또 하나, OSD-536은 표본 수가 작습니다(정확한 수는 2주차에 study record에서 직접 확인합니다). 표본이 작으면 우연히 생긴 차이가 진짜처럼 보이기 쉽습니다. 그래서 이 데이터의 결과는 "발견"이 아니라 "다음 실험에서 확인해 볼 후보"로 읽습니다.

### 프로젝트 폴더는 실험실 벤치다

실험실에서 시약, 샘플, 실험 노트, 결과 사진을 한 서랍에 섞어 두지 않듯이, 분석 프로젝트도 종류별로 자리를 정해 둡니다. 원칙은 세 가지입니다.

- **원본 데이터(`data/`)는 읽기만 한다.** 내려받은 파일을 직접 고치지 않습니다. -80℃ 냉동고의 원본 샘플과 같습니다. 고친 버전이 필요하면 코드로 만들어 다른 곳에 저장합니다.
- **코드(`notebooks/`, `src/`)와 결과물(`figures/`, `reports/`)을 분리한다.** 그림은 언제든 코드로 다시 만들 수 있어야 합니다. 그림 파일만 있고 만든 코드가 없으면, 프로토콜 없는 실험 결과와 같습니다.
- **설명서(`README.md`)를 맨 위에 둔다.** 6주 뒤의 나, 혹은 처음 보는 사람이 폴더를 열었을 때 가장 먼저 읽는 파일입니다.

### README와 commit은 실험 노트다

`README.md`는 프로젝트의 초록(abstract)이고, Git commit은 날짜가 찍힌 실험 노트 한 쪽입니다. commit을 남기면 "그날 그 시점의 폴더 전체 상태"가 사진처럼 저장되어, 나중에 무엇이 언제 바뀌었는지 되짚을 수 있습니다.

오늘 README에 범위와 한계를 **먼저** 적는 이유가 있습니다. 결과를 본 뒤에 한계를 쓰면, 사람은 자기 결과에 유리하게 쓰게 됩니다. 데이터를 열어 보기 전에 "여기까지만 주장하겠다"고 적어 두면, 그 문장이 6주 동안 스스로를 붙잡아 주는 난간이 됩니다.

### 예시 2 — 완성된 폴더 구조

오늘 실습을 마치면 폴더가 이렇게 됩니다(`lessons/`는 이미 있는 강의 자료 폴더입니다).

```text
neurodegeneration-bioinformatics/
├── README.md            ← 프로젝트 설명 (오늘 작성)
├── learning-log.md      ← 매일 10분씩 쓰는 학습 일지
├── environment.yml      ← 내 conda 환경의 기록
├── .gitignore           ← Git이 무시할 파일 목록
├── data/
│   ├── README.md        ← 데이터 출처·버전 기록 (3주차에 채움)
│   ├── osdr_536/        ← 마우스 분자 데이터
│   └── physionet_pd/    ← 사람 운동 데이터
├── notebooks/           ← Jupyter 노트북
├── reports/             ← 보고서
├── figures/             ← 그림
├── src/                 ← 여러 노트북에서 같이 쓰는 코드
└── lessons/             ← 강의 자료
```

두 데이터가 `data/` 안에서도 **서로 다른 폴더**에 들어간다는 점을 보세요. "합치지 않는다"는 원칙이 폴더 구조에도 그대로 나타납니다.

### 예시 3 — 좋은 commit 메시지와 나쁜 commit 메시지

| 나쁜 예 | 좋은 예 |
|---|---|
| `수정` | `Day 1: 프로젝트 폴더 구조와 README 추가` |
| `asdf` | `README에 해석 원칙 3가지 추가` |
| `최종_진짜최종` | `Day 4: 결측치·중복 ID 점검 함수 작성` |

좋은 메시지는 "무엇을 왜 바꿨는지"가 한 줄로 보입니다. 한 달 뒤 `git log`를 열었을 때 실험 노트의 목차처럼 읽혀야 합니다.

## 직접 해보기

모든 명령은 macOS의 **터미널(Terminal)** 앱에서 실행합니다. 설치는 0주차에 끝났으니 오늘은 하지 않습니다.

1. **프로젝트 폴더로 이동합니다.**

   ```bash
   cd ~/Documents/neurodegeneration-bioinformatics
   pwd
   ls
   ```

   `lessons`가 보이면 맞는 곳입니다. (프로젝트 폴더를 다른 위치에 두었다면 그 경로로 이동하세요.)

2. **0주차에 만든 conda 환경을 켭니다.** 환경 이름이 기억나지 않으면 목록부터 봅니다.

   ```bash
   conda env list
   conda activate neurobio
   python -c "import pandas, numpy, matplotlib; print('환경 OK')"
   ```

   `환경 OK`가 출력되면 통과입니다.

3. **폴더를 한 번에 만듭니다.** `-p`는 "중간 폴더도 같이 만들고, 이미 있으면 그냥 넘어가라"는 뜻입니다.

   ```bash
   mkdir -p data/osdr_536 data/physionet_pd notebooks reports figures src
   touch learning-log.md
   ls -F
   ```

   예상 출력(이미 있던 파일에 따라 조금 다를 수 있습니다):

   ```text
   README.md  data/  figures/  learning-log.md  lessons/  notebooks/  reports/  src/
   ```

4. **`README.md`에 프로젝트 소개를 붙입니다.** `>>`는 파일이 없으면 새로 만들고, 있으면 **맨 끝에 덧붙입니다.** 코스 지도가 이미 들어 있는 `README.md`가 있어도 지워지지 않습니다. 아래를 통째로 복사해 붙여 넣으세요.

   ```bash
   cat >> README.md <<'EOF'

   ## 프로젝트 소개

   6주 퇴행성 뇌질환 바이오인포매틱스 실습. 서로 독립된 두 프로젝트로 구성된다.

   1. NASA OSDR OSD-536: 우주비행 관련 마우스 뇌 신경염증 유전자 발현 데이터
   2. PhysioNet PADS: 사람의 파킨슨병 스마트워치 운동 데이터

   ## 이 프로젝트가 답하려는 질문

   우주비행 관련 마우스 뇌의 분자 변화와 파킨슨병 환자의 운동 표현형은
   퇴행성 신경질환 연구에서 어떤 기전적 가설을 제안할 수 있는가? (탐색적·교육적 질문)

   ## 해석 원칙과 한계

   - 마우스 분자 데이터와 사람 운동 데이터를 통계적으로 합치거나 인과로 연결하지 않는다.
   - 작은 표본의 결과는 가설 생성으로만 해석한다.
   - 모델 검증은 참가자 단위로 나눈다.
   - 진단이나 치료에 관한 주장을 하지 않는다.

   ## 폴더 구조

   - `data/` 원본 데이터 (읽기 전용, Git에 올리지 않음)
   - `notebooks/` 분석 노트북
   - `src/` 공용 코드
   - `figures/` 그림, `reports/` 보고서
   - `learning-log.md` 학습 일지
   EOF
   ```

   그다음 `open -e README.md`로 텍스트 편집기에서 열어, "해석 원칙과 한계" 아래에 **자기 말로 한 문장**을 더 적으세요. 예: "나는 결과가 흥미로워 보여도 '원인이다'라는 표현을 쓰지 않는다."

5. **`.gitignore`와 `data/README.md`를 만듭니다.** 내려받은 데이터는 용량이 크고 라이선스가 따로 있으니 Git에 올리지 않습니다.

   ```bash
   cat > .gitignore <<'EOF'
   # 내려받은 데이터는 Git에 올리지 않는다 (설명 파일만 예외)
   data/*
   !data/README.md

   # 자동으로 생기는 파일
   .ipynb_checkpoints/
   __pycache__/
   .DS_Store
   EOF

   echo "# 데이터 출처 기록 (3주차 Day 15에 채운다)" > data/README.md
   ```

   > 0주차에 이미 `.gitignore`를 만들었다면 `>`가 덮어쓰니, 이 단계 대신 `open -e .gitignore`로 열어 위 내용을 추가하세요.

6. **환경을 파일로 기록합니다.**

   ```bash
   conda env export --from-history > environment.yml
   cat environment.yml
   ```

   내가 직접 설치한 패키지 목록이 보이면 됩니다.

7. **Git 저장소를 확인하고 첫 commit을 남깁니다.**

   ```bash
   git status
   ```

   `fatal: not a git repository`가 나오면 아직 저장소가 아니니 `git init`을 한 번 실행합니다. 0주차에 이미 만들었다면 건너뜁니다. 그다음:

   ```bash
   git add README.md learning-log.md .gitignore environment.yml data/README.md
   git status --short
   git commit -m "Day 1: 프로젝트 폴더 구조와 README 추가"
   git log --oneline
   ```

   `git status --short`의 예상 출력(이미 commit한 파일은 `M`으로 나오거나 빠질 수 있습니다):

   ```text
   A  .gitignore
   A  README.md
   A  data/README.md
   A  environment.yml
   A  learning-log.md
   ```

8. **JupyterLab이 이 폴더에서 열리는지 확인합니다.**

   ```bash
   jupyter lab
   ```

   브라우저 왼쪽 파일 목록에 방금 만든 폴더들이 보이면 성공입니다. 터미널에서 `Ctrl + C`를 두 번 눌러 종료합니다.

9. **`learning-log.md`에 오늘 날짜와 세 줄을 적습니다.** 배운 점 1줄, 막힌 점 1줄, 내일 할 일 1줄.

> ⚠️ **흔한 오류 1 — `Author identity unknown`**
> commit할 때 이 메시지가 나오면 Git이 내 이름을 모르는 것입니다. 아래를 한 번만 실행하고 다시 commit하세요.
> ```bash
> git config --global user.name "내 이름"
> git config --global user.email "내 이메일"
> ```

> ⚠️ **흔한 오류 2 — 빈 폴더가 Git에 안 보인다**
> `git status`에 `notebooks/`, `figures/` 같은 폴더가 나오지 않아도 정상입니다. Git은 **파일**만 추적하고 빈 폴더는 무시합니다. 안에 파일이 생기면 그때 나타납니다.

</details>

**2.** OSD-536과 PADS 데이터를 한 표로 합쳐 상관분석을 하지 않는 이유를 두 가지 이상 쓰세요. (단답)

**3.** `data/` 폴더의 원본 파일을 직접 수정하지 않는 이유로 가장 알맞은 것은?

- (a) 파일 용량이 커지기 때문에
- (b) 원본이 바뀌면 분석을 처음부터 다시 재현할 수 없기 때문에
- (c) Git이 오류를 내기 때문에
- (d) Python이 수정된 파일을 읽지 못하기 때문에

<details><summary>정답 보기</summary>

**4.** `.gitignore`에 `data/*`와 `!data/README.md`를 함께 쓴 이유는? (단답)

<details><summary>정답 보기</summary>

`data/*`는 data 폴더 안의 모든 것을 Git이 무시하게 하고, `!data/README.md`는 그중 설명 파일 하나만 예외로 다시 추적하게 합니다. 데이터 자체는 올리지 않되, "어디서 무엇을 받았는지"에 대한 기록은 남기기 위해서입니다.

</details>

결과를 본 뒤에는 자기 결과에 유리하게 한계를 느슨하게 쓰기 쉽기 때문입니다. 미리 "여기까지만 주장한다"고 적어 두면, 나중에 흥미로운 결과가 나와도 과장하지 않도록 스스로를 붙잡아 줍니다.

</details>
