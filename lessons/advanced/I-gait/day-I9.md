## 개념 설명

### 가속도계: 중력과 움직임을 구분하지 못한다

가속도계는 내부의 작은 질량에 걸리는 반력을 재는 **힘 변환기**입니다([Wi] 3.2.2 pp.38–39). 질량을 밀거나 끄는 것이 움직임이든 중력이든 센서는 구분하지 않습니다. 그래서 책상 위에 놓인 3축 가속도계는 위쪽 축에서 약 1 g(9.81 m/s²)를 읽습니다. 엘리베이터 안에서 체중계 눈금이 출발할 때 늘었다가 멈출 때 줄어드는 것과 같은 원리입니다. 체중계도 "중력 + 가속"을 함께 잽니다.

이 성질은 장점이자 함정입니다. **장점:** 가만히 있을 때는 중력만 보이므로, 세 축에 중력이 어떻게 나뉘었는지로 센서의 **기울기**를 알 수 있습니다(예시 1). 정적 응답(DC 응답)이 있는 종류(strain gauge, piezoresistive)는 바로 이 성질을 이용해 민감축을 중력에 맞춰 보정하고, 정적 응답이 없는 piezoelectric 종류는 느린 변화나 정지를 재지 못합니다([RM] 1장 pp.21–22). 센서 사양서에서 "정지 = 0"인지 "정지 = 1 g"인지를 먼저 확인해야 하는 이유입니다. **함정:** 걷는 중에는 중력 위에 다리의 **선가속도**가 더해지므로, 같은 계산이 기울기를 크게 틀리게 줍니다. 분절이 회전하면 같은 공간 가속도라도 센서 축에 나뉘는 성분이 달라진다는 점도 있습니다([Wi] 3.2.2).

### 자이로: 각속도를 잘 재지만, 적분하면 흘러간다

**자이로스코프(gyroscope)** 는 각속도(°/s)를 잽니다. 각도를 얻으려면 시간에 대해 적분(누적 합)해야 하는데, 센서의 영점이 조금만 어긋나 있어도(**bias**) 그 어긋남이 매 순간 더해져 각도 오차가 **시간에 비례해** 커집니다. 이것이 **drift**입니다. 시계가 하루에 10초씩 빨라지면 한 달 뒤 5분이 틀리는 것과 같습니다. 무작위 잡음도 적분되면서 조금씩 쌓입니다.

[Wi]는 drift를 줄이는 방법으로 세 가지를 듭니다([Wi] 3.2.3 p.39): ① 알려진 정지 자세에서 각도를 다시 맞추기(이때 가속도계 기울기를 씀), ② 자이로와 가속도계(때로 자력계)를 합치는 **센서 융합** 알고리즘, ③ high-pass 필터. ②의 가장 단순한 형태인 complementary filter는 [Day I11](day-I11.md)에서 직접 만듭니다. 오늘은 둘의 성격을 기억하세요. **가속도계 기울기는 길게 보면 맞지만 순간순간 흔들리고, 자이로 적분은 순간순간 매끄럽지만 길게 보면 흘러간다.**

### 세 개의 좌표계

같은 움직임도 어느 좌표계로 보느냐에 따라 숫자가 다릅니다.

- **전역 좌표계(global):** 실험실(또는 지구)에 고정된 축. 힘판과 카메라가 쓰는 축입니다([Wi] 7.1 pp.145–148).
- **분절(해부학) 좌표계(anatomical / segment):** 뼈 지표로 정한, 분절과 함께 움직이는 축. "굴곡", "외전" 같은 이름은 이 축에서만 의미가 있습니다.
- **센서 좌표계(sensor):** 센서 칩 자체의 축. 센서를 피부에 붙이는 순간의 각도에 따라 분절 축과 어긋납니다.

IMU가 주는 숫자는 **센서 좌표계의 성분**입니다. 정강이에 붙인 센서가 장축 둘레로 20° 돌아가 붙으면, 같은 시상면 회전이 센서의 두 축으로 나뉘어 읽힙니다. 세 성분의 **크기**만 좌표계와 무관합니다(예시 3). 그래서 "이 축 = 무릎 굴곡"이라고 부르기 전에 센서와 분절의 관계를 정해야 하고, [Wi]는 그 방법으로 수동 정렬(센서 축을 관절 축에 맞춰 붙이고 정지 자세로 보정), 기능적 정렬(정해진 동작으로 관계를 추정. 환자가 동작을 못 하면 쓸 수 없음), 모델 기반 추정을 소개합니다([Wi] 3.2.3 pp.39–40). 3차원 회전에서는 각속도 성분을 따로 적분해도 각도가 되지 않는다는 문제도 있어서(회전축이 고정된 경우에만 적분 = 각도), 입문 실습은 **시상면 한 축**으로 한정합니다([BMC] `angular_velocity_3d`).

### 어디에 붙일까: 부착 위치가 보이는 정보를 정한다

| 부착 위치 | 잘 보이는 것 | 실제 연구 예 |
|---|---|---|
| 발목 위(정강이, shank) | 발 접지·유각의 리듬, 다리 떨림 | Moore 2008: 왼쪽 shank의 수직 가속도를 100 Hz로 기록해 FOG를 판정([초록](https://doi.org/10.1016/j.jneumeth.2007.08.023)) |
| 허벅지(무릎 위) | 허벅지 분절의 앞뒤 흔들림 | Bächlin 2010: shank·thigh·허리 3개 센서, 64 Hz(II-A·II-C절) |
| 허리·골반 | 몸통의 상하·좌우 움직임, 걸음 리듬 | Bächlin 2010의 세 번째 센서(Daphnet 자료의 "Trunk" 채널, 부착은 엉덩이 높이) |
| 손목 | 팔 흔들기, 떨림, 일상 활동 | [Day 22](../../week-4/day-22.md)의 스마트워치 자료 |

Bächlin 2010은 세 센서를 모두 기록했지만 **온라인 검출에는 shank 센서 하나**만 썼고, 사후 비교에서는 수직축 기준으로 허벅지가 가장 좋고(민감도/특이도 85/88%) 발목 81/87%, 허리 71/79% 순이었다고 보고합니다(V-B절, 전체 참가자 공통 매개변수 기준). 허벅지는 성능은 좋지만 착용이 가장 불편한 위치라는 평도 함께 붙입니다.

손목은 어떨까요? 환자가 가장 받아들이기 쉬운 위치는 손목이고, 해석은 몸통 센서가 더 쉽다고 정리됩니다([Mirelman 2019](https://doi.org/10.1016/S1474-4422(19)30044-4)). 손목 신호에는 다리 대신 팔 흔들기가 주로 보이므로 FOG 검출에 불리하다고 생각하기 쉽지만, 손목 센서 하나로 발목 센서와 비슷한 성능을 냈다는 연구를 소개하는 리뷰도 있습니다([Guo 2022](https://doi.org/10.3389/fnagi.2022.916971)가 인용한 Mazilu 2016, 원문은 이 과정에서 확인하지 않음). **"손목으로는 FOG를 볼 수 없다"고 단정하지 말고, "문헌에 따라 결과가 갈린다"** 정도로 이해해 둡니다.

표본화 주파수도 사양의 일부입니다. Daphnet(64 Hz)의 Nyquist 주파수는 32 Hz여서 FOG 떨림 대역(3–8 Hz, [Day I18](day-I18.md))을 충분히 담습니다. 진폭 쪽 해상도(A/D 비트 수, 측정 범위)는 시간 해상도와 별개의 축이라는 것도 기억해 두세요([BMC] `signal_basic_properties`).

## 예시로 이해하기

> 예시 1–3은 코드 안에서 만든 **가상 신호**, 예시 4는 실제 공개 데이터입니다.

### 예시 1 — 정지 자세의 기울기, 그리고 움직일 때의 오류

```python
import numpy as np

rng = np.random.default_rng(9)
fs = 100
true_tilt = 20.0                     # 정강이가 앞으로 20° 기울어 서 있다(가상)
th = np.deg2rad(true_tilt)
n = 2 * fs                           # 2초 기록
# 센서 x축 = 정강이 앞쪽, z축 = 정강이 장축(위쪽). 정지 상태에서는 중력만 보인다(단위 g)
ax = np.sin(th) + rng.normal(0, 0.01, n)
az = np.cos(th) + rng.normal(0, 0.01, n)
tilt = np.rad2deg(np.arctan2(ax, az))
print(f"정지: 가속도 크기 평균 {np.mean(np.hypot(ax, az)):.3f} g, 추정 기울기 {tilt.mean():.2f}° (참값 {true_tilt}°)")

# 같은 자세에서 센서 x축 방향으로 0.3 g의 선가속도가 더해지는 순간(예: 발을 내딛는 중)
tilt_move = np.rad2deg(np.arctan2(ax + 0.3, az))
print(f"움직임: 추정 기울기 {tilt_move.mean():.1f}° → 선가속도가 기울기처럼 읽힌다")
```

실행 결과:

```text
정지: 가속도 크기 평균 1.000 g, 추정 기울기 20.02° (참값 20.0°)
움직임: 추정 기울기 34.4° → 선가속도가 기울기처럼 읽힌다
```

`arctan2(앞쪽 성분, 장축 성분)`이 기울기입니다(`arctan`이 아니라 사분면을 구분하는 `arctan2`). 가만히 있으면 0.01 g 잡음에도 0.02° 이내로 맞지만, 0.3 g의 선가속도 하나로 14° 넘게 틀어집니다. 걷는 동안 정강이의 선가속도는 이보다 클 때가 많습니다.

### 예시 2 — bias가 있는 자이로를 60초 적분하기

```python
import numpy as np

rng = np.random.default_rng(90)
fs = 100
t = np.arange(0, 60, 1 / fs)          # 60초
true_rate = np.zeros_like(t)          # 실제로는 전혀 돌지 않는다(가만히 놓인 센서)
for bias in [0.1, 0.5, 1.0]:          # 자이로의 영점 어긋남(°/s)
    gyro = true_rate + bias + rng.normal(0, 0.5, len(t))   # bias + 백색 잡음 0.5 °/s
    angle = np.cumsum(gyro) / fs                           # 적분 → 각도(°)
    e = [angle[int(s * fs) - 1] for s in (10, 30, 60)]
    print(f"bias {bias:.1f} °/s → 각도 오차 10 s {e[0]:5.1f}°, 30 s {e[1]:5.1f}°, 60 s {e[2]:5.1f}°")
```

실행 결과:

```text
bias 0.1 °/s → 각도 오차 10 s   0.9°, 30 s   2.8°, 60 s   5.3°
bias 0.5 °/s → 각도 오차 10 s   4.6°, 30 s  14.9°, 60 s  29.5°
bias 1.0 °/s → 각도 오차 10 s  10.2°, 30 s  30.4°, 60 s  60.3°
```

오차는 거의 정확히 **bias × 시간**입니다(0.5 °/s × 60 s = 30°). 센서는 전혀 돌지 않았는데 1분 뒤 30° 기울었다고 말합니다. 몇 초짜리 한 걸음 안에서는 자이로 적분이 쓸 만하지만, 몇 분짜리 기록의 "절대 각도"로는 쓸 수 없습니다.

### 예시 3 — 센서를 비뚤게 붙이면 같은 회전이 다른 숫자로 읽힌다

```python
import numpy as np

# 정강이 분절 좌표: x = 앞, y = 내외측 축, z = 장축(위)
w_anat = np.array([0.0, 300.0, 0.0])        # 시상면 회전 300 °/s → 내외측 축(y) 성분만 있다

def rot_z(deg):                              # 장축(z) 둘레로 센서를 돌려 붙였을 때의 변환
    c, s = np.cos(np.deg2rad(deg)), np.sin(np.deg2rad(deg))
    return np.array([[c, s, 0], [-s, c, 0], [0, 0, 1]])

for mis in [0, 10, 20, 30]:
    w_sensor = rot_z(mis) @ w_anat           # 센서가 자기 축으로 읽는 값
    print(f"장축 둘레 {mis:2d}° 어긋남 → 센서 x {w_sensor[0]:6.1f}, y {w_sensor[1]:6.1f}, "
          f"z {w_sensor[2]:4.1f} °/s | 크기 {np.linalg.norm(w_sensor):.1f}")
```

실행 결과:

```text
장축 둘레  0° 어긋남 → 센서 x    0.0, y  300.0, z  0.0 °/s | 크기 300.0
장축 둘레 10° 어긋남 → 센서 x   52.1, y  295.4, z  0.0 °/s | 크기 300.0
장축 둘레 20° 어긋남 → 센서 x  102.6, y  281.9, z  0.0 °/s | 크기 300.0
장축 둘레 30° 어긋남 → 센서 x  150.0, y  259.8, z  0.0 °/s | 크기 300.0
```

몸은 똑같이 움직였는데 "y축 최댓값"은 300에서 260으로 줄고, 원래 0이어야 할 x축에 150이 생깁니다. 두 사람의 y축 값을 비교했는데 차이가 **센서 부착 각도** 때문일 수 있다는 뜻입니다. 크기(`norm`)만 그대로입니다. 이 아이디어는 BMC `angular_velocity_3d` 노트북의 "정강이 자이로" 절에서 빌렸고 코드는 새로 썼습니다.

### 예시 4 — 실제 자료: 세 축 크기의 중앙값은 1 g 근처

**데이터:** Roggen D, Plotnik M, Hausdorff J. *Daphnet Freezing of Gait* [Dataset]. UCI Machine Learning Repository; 2010. [doi:10.24432/C56K78](https://doi.org/10.24432/C56K78). 라이선스 CC BY 4.0. 사용 시 Bächlin 2010 인용이 요구됩니다. [UCI 페이지](https://archive.ics.uci.edu/dataset/245/daphnet+freezing+of+gait)에서 zip을 받아 풀고, `dataset/S01R01.txt`를 `data/daphnet/`에 둡니다. (zip 안에 든 논문 PDF는 재배포하지 않습니다.) 파일 구조: 머리글 없음, 공백 구분 11열, 1열 시간(ms), 2–4열 발목(shank)의 앞뒤·수직·좌우 가속도(mg), 5–7열 허벅지, 8–10열 엉덩이 높이 센서, 11열 라벨(0 = 실험 외, 1 = 실험 중 FOG 아님, 2 = FOG), 64 Hz.

```python
import numpy as np

fs = 64                                           # Daphnet 표본화 주파수(데이터 문서)
d = np.loadtxt("data/daphnet/S01R01.txt")         # 머리글 없음, 공백 구분 11열
label = d[:, 10]                                  # 0 = 실험 외, 1 = FOG 아님, 2 = FOG
shank = d[:, 1:4]                                 # 2–4열: 발목(shank) 전후·수직·좌우, 단위 mg
on = label == 1                                   # 실험 중이고 FOG가 아닌 구간만
mag = np.linalg.norm(shank[on], axis=1)
print(f"기록 길이 {len(d) / fs / 60:.1f}분, 라벨 1 구간 {on.sum() / fs / 60:.1f}분")
print(f"축별 평균(mg): 전후 {shank[on, 0].mean():.0f}, 수직 {shank[on, 1].mean():.0f}, 좌우 {shank[on, 2].mean():.0f}")
print(f"세 축 크기의 중앙값 {np.median(mag):.0f} mg (1 g = 1000 mg)")
```

실행 결과:

```text
기록 길이 39.6분, 라벨 1 구간 22.8분
축별 평균(mg): 전후 -250, 수직 963, 좌우 361
세 축 크기의 중앙값 1052 mg (1 g = 1000 mg)
```

라벨 1 구간에는 서기·걷기·회전이 모두 섞여 있는데도 수직축 평균이 약 960 mg, 크기의 중앙값이 약 1050 mg입니다. 움직임 성분은 위아래로 오가며 평균에서 상쇄되고, **늘 같은 방향으로 남는 중력**이 평균을 차지합니다. 앞뒤·좌우 축의 평균이 0이 아닌 것은 센서가 정강이에 완전히 수직으로 붙지 않았다는 뜻입니다(예시 3과 같은 정렬 문제).

## 직접 해보기

1. `notebooks/advanced/I/I9_imu_basics.ipynb`를 만들고 예시 1–4를 실행합니다.
2. 예시 1에서 선가속도를 0.1, 0.3, 0.5 g로 바꿔 기울기 오차를 표로 만듭니다. "기울기 오차 ≈ arctan(선가속도 / 1 g)"인지 확인하세요.
3. 예시 2에서 `bias = 0`으로 두고 잡음만 있을 때 60초 오차를 10번 반복해 봅니다(seed를 바꿔 가며). 잡음만으로도 오차가 0이 아니고, 부호가 매번 바뀌는 것(random walk)을 확인합니다.
4. 예시 2의 마지막에 "10초마다 가만히 서 있는 순간이 있고, 그때 각도를 0으로 다시 맞춘다"는 규칙을 넣어 보세요(`angle`을 10초 구간마다 따로 적분). 60초 오차가 얼마나 줄어드나요? [Wi]의 첫 번째 drift 보정 방법입니다.
5. 예시 4를 라벨 2(FOG) 구간에도 적용하고, 세 센서(발목 2–4열, 허벅지 5–7열, 엉덩이 높이 8–10열)의 수직축 **표준편차**를 라벨 1과 2에서 비교하는 표를 만듭니다. 어느 위치에서 차이가 가장 큰지 적어 두세요(Day I18에서 다시 씁니다). 참가자 한 명의 결과이므로 일반화하지 않습니다.
6. 노트북 끝에 "부착 위치 표"를 내 말로 다시 쓰고, 연구 질문 하나(예: FOG 일상 모니터링)에 어느 위치를 고를지 두 줄로 적습니다.

> ⚠️ **흔한 오류 1:** Daphnet 시간 열(ms)의 간격으로 표본화 주파수를 계산하면 15–16 ms가 섞여 나옵니다(64 Hz = 15.625 ms를 정수로 반올림해 저장). 표본화 주파수는 문서의 64 Hz로 고정하고, 시간 열은 확인용으로만 씁니다.
>
> ⚠️ **흔한 오류 2:** 각도는 deg로, 삼각함수와 미분·적분 계산은 rad로 해야 하는데 둘을 섞는 것. `np.sin(20)`은 20°가 아니라 20 rad의 사인입니다. `np.deg2rad`를 습관처럼 씁니다.

## 퀴즈

**1.** 책상 위에 가만히 놓인 3축 가속도계의 위쪽 축은 약 몇 g를 읽나요? 그 이유는?

<details><summary>정답 보기</summary>

약 **1 g**. 가속도계는 내부 질량에 걸리는 힘을 재므로 움직임과 중력을 구분하지 못합니다. 정지해 있어도 중력이 질량을 끌어당기는 만큼의 값이 나옵니다(정적 응답이 있는 종류 기준).

</details>

**2.** bias 0.2 °/s인 자이로를 5분 동안 적분하면 각도 오차는 대략 몇 도인가요?

<details><summary>정답 보기</summary>

약 **60°** (0.2 °/s × 300 s). bias에 의한 drift는 시간에 비례해 커집니다. 여기에 잡음의 누적(random walk)이 조금 더해집니다.

</details>

**3.** 걷는 중에 가속도계만으로 정강이 기울기를 구하면 왜 틀리기 쉬운가요?

<details><summary>정답 보기</summary>

걷는 동안에는 중력 위에 다리의 선가속도가 더해지는데, 기울기 공식은 "보이는 가속도는 모두 중력"이라고 가정하기 때문입니다. 선가속도가 기울기처럼 읽힙니다. 그래서 짧은 시간의 변화는 자이로에, 긴 시간의 기준은 가속도계에 맡기는 센서 융합(Day I11)을 씁니다.

</details>

**4.** 두 참가자의 정강이 자이로 y축 최댓값이 각각 300과 260 °/s였습니다. "두 번째 사람의 다리 회전이 느리다"고 결론 내리기 전에 무엇을 확인해야 하나요?

<details><summary>정답 보기</summary>

센서 부착 방향(센서 좌표계와 분절 좌표계의 관계)입니다. 예시 3처럼 장축 둘레로 30° 비뚤게 붙으면 같은 300 °/s 회전이 y축에서 260으로 읽힙니다. 정렬 보정을 했는지, 또는 좌표계와 무관한 세 축 크기를 비교했는지 확인합니다.

</details>

**5.** Bächlin 2010의 세 센서 중 온라인 FOG 검출에 실제로 쓴 것은? 그리고 "손목 센서로는 FOG를 볼 수 없다"는 문장은 맞는가?

<details><summary>정답 보기</summary>

온라인 검출에는 **shank(발목 위) 센서 하나**만 썼습니다(허벅지·허리는 사후 비교용). 손목에 대한 문장은 단정하기 어렵습니다. 손목 센서로도 발목과 비슷한 성능을 냈다는 연구가 리뷰에 소개되어 있어, "결과가 갈린다"가 정확한 표현입니다.

</details>
